## Demo acceptance scenario

One owned assessment: authorized request → genuine network/web imports → inspect normalized finding and source evidence → identify an unanswered or conflicting declared question → show an actual model recommendation and meaningful alternative → exact approval → bounded execution → inspect updated evidence → download the report.

Additional regression demonstrations: failed observation does not prove absence, excluded action is blocked, imported instructions cannot authorize work. Label mocked and synthetic material visibly. If a live provider is unavailable, show a clearly labelled previously recorded genuine run; do not present development rules as AI.

## Stretch work and exclusions

Remediation/retest comparison is a PS-1 bonus, after mandatory gates pass. A one-header retest demonstrates that condition only and is not exploit validation. Broader active validation requires a separately reviewed exact lab action; do not add arbitrary shell or autonomous exploitation. No new agent framework, provider switching, compliance certification claims or broad dashboard expansion.

Tradeoff: genuine imports satisfy the published checklist with less operational complexity, but do not establish autonomous scanner orchestration. Keep that limitation visible. AI remains required for the reasoning demonstration; deterministic eligibility is the safety boundary and useful fallback mode, not evidence of model reasoning.
